Part of the [world inventory](../WORLD_INVENTORY.md) (docs/PLAN.md M4 #4). Upstream OpenSWOS at
`df643c2`; line numbers are at that commit. The `rules/` files and components proposed
here are merged into one design in the inventory, whose §12 maps each name used here to its final one.

Upstream OpenSWOS at df643c2. Area: world identity, the baked tables, loading a world, teams, and
the rest that is not competitions or the career. Line numbers are at this pin. "(unsure)" marks a
guess.

Short names used below:
- 9697 = WORLD_9697 (the original), 2627 = World 2026-27, 8485 = Europe 1984-85.
- "completion" = our step that turns a world into a self-contained package.
- `#if SWOS_WORLDS` that only switches the whole worlds feature off at build time is counted as
  NOT_A_BRANCH (no row), unless it changes a capacity (then LIMIT).

## The JSON overlay: what a world installs over 96/97 (save_format_json.c)

Start-up order (frontend.c 133-161): `World_InstallBaked` (baked records over the compiled ones)
-> `DataJson_FitModTeamFiles` (a world: national files' number ranges) ->
`DataJson_InstallCompetitionGraph` (96/97's JSON plus the world's overlay, over the baked) ->
`WorldCups_Install` -> career params -> `DataJson_LoadNationalTeams` -> `WorldNationals_Install`
-> `TeamDb_Apply` and `TeamDb_ApplyLeagueTweaks` (both 96/97 only).

A world's files sit in `data_json/worlds/<tag>/` beside 96/97's, same relative path
(`dj_world_path`, 4059-4069). The world package ships only `teams/`, `competitions/leagues.json`,
2627's `competitions/national_teams.json`, `competitions/stadiums.json`, `competitions/bteams.json`,
`teams/POOLPLYR.DAT`, `data/TEAM.nnn`, WORLD.ini and mod.json (scripts/make_world_package.sh 9-16;
bteam.c 136, world_stadium.c 46, transfer_market.c 643).

So the merge our completion must reproduce: start from 96/97's files; replace each team file the
world has, whole; add the world's new team files; replace competition records by `id` (keeping 96/97's
play-off links); add the baked-only records (new countries' leagues, cups, tables, renames,
codes, team-number bases, region lists, season order) from the baked tables; then write the world's
rules/*.json from the accessor tables.

**Rows per class.** Branch rows (8 columns): DATA 45, SAVE 13, LIMIT 12, VIEW 19, OUT_OF_SCOPE 18,
COMPONENT 0. Baked table (6 columns): 31 rows, 30 DATA and 1 COMPONENT (FixtureRounds_Install).

2215-2222), the menu_data.h 1405 comment, and WorldPacks_Use/UseAt's "not the world being played"

`World_Current()` (22 in world_data.c, 24 in world_data_8485.c). That only repeats the dispatch, so those checks are not counted.

  `league_max_divisions` 16, `nationality_codes` 223, `region_countries` 56, `euro_places` 40,

- rules/nationality_codes.json: code overrides (2627: 5).

- rules/tweaks.json: whether the SWOS 2020 league tweaks apply (9697 only) (unsure).

**Components:**
- OddClubFixtures: no component since M5 #1. The two ways are two tables: 9697's compiled
  `_fixtureSchedulePtrTable` and 2627's and 8485's after fixture_rounds.c
  `FixtureRounds_Install`, so they are data, rules/fixtures.json `schedules`.
- Hint for the competitions inventory: the European cups have three forms (9697 compiled knockouts
  with seed buckets; 8485 knockout records + places, world_europe.c `WorldEurope_Install`; 2627
  league phases, league_phase.c `LeaguePhase_InstallCups`).

**The JSON overlay (save_format_json.c):** a world's files sit in `data_json/worlds/<tag>/` beside
96/97's. A team file is replaced whole; a new country's or pool's file is the world's alone. In
cups.json, leagues.json, tournaments.json and playoffs.json a world record replaces 96/97's record
of the same `id` (compId must match; league play-off links stay 96/97's); world-only ids are
ignored there. national_teams.json is the world's whole file if it has one. countries.json,
country_competitions.json, qualifying.json, league_blocks.json, seed_buckets.json and career.json
are never overlaid: a world's new countries, tables, renames, codes, number bases, region lists
and season order come only from the baked install, which runs first.

**Surprising or uncertain:**
- Second team files are fully plumbed but unused at this pin: the generated switches are empty
  (Italy -> 197 is planned).
- 2627's Europe list has 55 countries; the region struct holds 44, so upstream keeps it outside.
- Three rules hang on `first_year` thresholds: national team renames (>= 2019), euro sign
  (>= 2002), stoppage era (stoppage.c, >= 2000). Better made explicit data than kept as thresholds.
- Several career save sections are written for any world but 9697 (euro holders, UEFA prizes,
  FFP, squad extras, B teams, world rules), even for 8485, whose mod.json has no career settings.
  A per-section package flag is needed to keep saves identical.
- Upstream switches the world to 9697 for a moment to read 96/97's team files (team_db.c 148-151,
  custom_team.c 388-402). Our port needs a "base package" for custom teams made from 96/97 clubs.
- On SDL a league is set twice: the baked record, then the JSON overlay of leagues.json. The two
  should match (same generator), but completion should take the JSON one.
- I did not open the 8485 package, so whether it carries its own national_teams.json and national
  files is unsure.
